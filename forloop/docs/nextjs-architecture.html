O.M.N.I — Next.js + Supabase Architecture Blueprint

Student organization portal — full rewrite of the Express + EJS + MySQL app

Source: forloop/ · Target: Next.js 15 (App Router) + Supabase (Postgres · Auth · Storage · pg_cron) · v1.0

1. Overview

O.M.N.I is a campus student-organization portal with three portals and a public site. The current implementation is a single Express app: server-rendered EJS views, hand-rolled scrypt sessions, callback-style mysql2, and no build step. This document specifies the complete rewrite to Next.js 15 App Router + Supabase as a TypeScript codebase.

User matrix (unchanged semantics)

PersonaWhoPortal
VisitorNot signed in/ · /login · /register
Non-memberStudent with 0 memberships/nonmember (reduced nav)
MemberStudent with ≥ 1 membership/student
AdviserRuns exactly one organization/admin
Golden rule: the portal split is derived from membership count, not a role. Approving a non-member's application must auto-graduate them to /student; removing a member from their last organization must demote them to /nonmember. Preserve this exactly.

Rewrite goals

  • Preserve every URL path (/student/discover, /admin/events/:id/attendance, …) so bookmarks and habits survive.
  • Preserve per-request authority: role, org, and membership count are read fresh on every render — never trusted from the cookie alone.
  • Replace the 5-dependency Express stack with Next.js + Supabase; TypeScript everywhere; typed query layer.
  • Fix known gaps (rate limiting, email verification, in-process cron) while rewriting.
  • Port the seeded demo data (4 orgs, 43 users, 5 events incl. one full event to demo the waitlist) so dev experience matches.

5. Data Model (Postgres)

13 tables, one-to-one mapping from MySQL. MySQL ENUM → CHECK constraints; users splits into Supabase auth.users + a profiles table keyed by auth.uid(). All FKs keep the original cascade rules. 

-- 0001_schema.sql (sketch — full DDL in supabase/migrations/)
create table profiles (
  id uuid primary key references auth.users on delete cascade,
  full_name text not null,
  email text not null unique,
  role text not null check (role in ('student','adviser')),
  student_id text unique,
  program text, year_level text, contact text, college text,
  bio text, hobbies text,
  avatar text,
  profile_complete boolean not null default false,
  org_id bigint references organizations on delete set null,  -- adviser's org
  created_at timestamptz not null default now()
);

create table organizations (
  id bigint generated always as identity primary key,
  name text not null, description text, category text not null default 'Technology',
  tags text, eligibility text,
  color text not null check (color in
    ('yellow','teal','lime','lilac','salmon','sky','rose','sand','black','red','brown','orange','white')),
  logo_img text, logo_style text not null default 'tile'
    check (logo_style in ('tile','navy','cream','dark')),
  meeting_schedule text,
  satisfaction numeric(2,1),
  created_at timestamptz not null default now()
);

create table org_roles (
  id bigint generated always as identity primary key,
  org_id bigint not null references organizations on delete cascade,
  role_title text not null, precedence int not null, is_officer boolean not null default false,
  unique (org_id, role_title)
);

create table memberships (
  id bigint generated always as identity primary key,
  org_id bigint not null references organizations on delete cascade,
  user_id uuid not null references profiles on delete cascade,
  role_title text not null default 'Member',
  joined_at timestamptz not null default now(),
  unique (org_id, user_id)
);

create table applications (
  id bigint generated always as identity primary key,
  org_id bigint not null references organizations on delete cascade,
  user_id uuid not null references profiles on delete cascade,
  intro text, status text not null default 'pending'
    check (status in ('pending','approved','rejected')),
  created_at timestamptz not null default now(), reviewed_at timestamptz,
  unique (org_id, user_id)
);

create table events (
  id bigint generated always as identity primary key,
  org_id bigint not null references organizations on delete cascade,
  title text not null, event_date date not null, event_time time,
  location text, description text,
  status text not null default 'draft' check (status in ('draft','published')),
  capacity int,                              -- null = unlimited
  attendance_taken boolean not null default false,
  reminder_sent boolean not null default false
);

create table event_program (
  id bigint generated always as identity primary key,
  event_id bigint not null references events on delete cascade,
  position int not null, start_time time, title text not null, speaker text
);

create table rsvps (
  event_id bigint not null references events on delete cascade,
  user_id uuid not null references profiles on delete cascade,
  seq bigint generated always as identity,   -- waitlist order (UNIQUE)
  status text not null check (status in ('going','waitlist')),
  attended boolean not null default false,
  primary key (event_id, user_id)
);

create table bookmarks (
  user_id uuid not null references profiles on delete cascade,
  org_id  bigint not null references organizations on delete cascade,
  primary key (user_id, org_id)
);

create table notifications (
  id bigint generated always as identity primary key,
  user_id uuid not null references profiles on delete cascade,
  message text not null, is_read boolean not null default false,
  created_at timestamptz not null default now()
);

create table announcements (
  id bigint generated always as identity primary key,
  org_id bigint not null references organizations on delete cascade,
  title text not null, body text not null,
  kind text not null check (kind in ('update','recruitment')),
  closes_on date, created_at timestamptz not null default now()

  id bigint generated always as identity primary key,
  org_id bigint not null references organizations on delete cascade,

5.1 Row-Level Security (backstop, not the primary gate)

TablePolicy sketch
profilesselect/update own row; advisers can select members of their org
membershipsselect all (directory is member-gated in app layer); write via service role only
organizationsselect all; update only adviser whose org_id matches
applications / application_answersselect own; insert own (pending only); adviser of org can select/update
events / event_programselect published; adviser of org full CRUD

bookmarksown rows only

Server-side query functions use the service-role client for trusted server code (mirroring today's single-DB-connection trust model) and the user client wherever a browser call is unavoidable (upload confirmations, realtime later). RLS keeps a compromised client from wandering.

5.2 Seed parity (supabase/seed.sql ≡ setup.js)

  • 4 organizations, 43 profiles (all demo password), 37 memberships, 7 applications (mixed statuses), 5 events (1 draft), programs, 12 RSVPs — the "Debugging 101" event seeded full (12/12) to demo the waitlist.
  • Dates computed relative to current_date so "upcoming" stays upcoming.
  • One scrypt hash today → seed Supabase auth users via the admin API in a seed script (scripts/seed.ts) instead of raw SQL, since auth users can't be inserted by plain SQL.

6.2 Enforcement layers

8. Feature Specs (the tricky bits)

8.1 RSVP + waitlist state machine

toggleRsvp(eventId, userId):
  ev = published event, event_date >= today            # else reject
  r  = existing rsvp
  if r going   → delete rsvp; promoteWaitlist(ev)      # free seat → first waiting
  if r waitlist→ delete rsvp
  else:
    if capacity is null or going_count < capacity → insert 'going'
    else → insert 'waitlist' (seq orders the queue)

promoteWaitlist(ev):                                   # used by cancel, capacity raise
  while capacity is null or going_count < capacity:
    pick lowest-seq 'waitlist' row → set 'going' + notify; stop if none

Runs inside a transaction. Capacity null = unlimited (no waitlist ever). The seed's full event (12/12) must demonstrate join→waitlist→cancel→promotion.

8.2 Applications pipeline

  • Orgs define ≤ 5 questions (org_questions, ordered).
  • Apply → one applications row (unique per org+user, allows re-apply after rejection) + application_answers rows that copy the question text (denormalized on purpose — later edits must not rewrite history).
  • Approve → insert memberships (default 'Member') + notification. Decline → status + notification.

8.5 Reminders (pg_cron)

-- hourly
create function send_event_reminders() returns void as $$
  insert into notifications (user_id, message)
  select r.user_id,
         'Reminder: ' || e.title || ' is on ' || e.event_date ||
         ' at ' || coalesce(e.event_time::text, 'TBD') || '.'
  from rsvps r
  join events e on e.id = r.event_id
  where r.status = 'going'
    and e.status = 'published'
    and e.event_date between current_date and current_date + 1
    and e.reminder_sent = false;

  update events set reminder_sent = true
  where status = 'published'
    and event_date between current_date and current_date + 1;
$$ language sql;

select cron.schedule('event-reminders', '0 * * * *', 'select send_event_reminders()');
